# 后续计划

## 公开部署前必须完成

以下两项当前为方便本地功能测试而暂缓，不代表风险已经接受。任何公网、生产或包含真实用户数据的部署都必须先完成整改并重新执行安全验收。

## 配置约定：数据库统一使用 `dayline`

- 后续本地开发、测试、Docker、部署文档和环境变量中的数据库名称统一写为 `dayline`。
- `dayliane` 仅保留为当前产品标识、Java 包名或历史目录中的旧名称，不得再作为数据库名称使用。
- 本次不做目录、包名和产品文案的大范围重命名，避免影响现有功能测试；只要涉及数据库连接，优先检查 `DB_NAME=dayline`。

### 1. 移除固定明文演示账号

- 将 `V2__seed_demo_users.sql`、`V4__seed_admin_user.sql`、`V6__seed_demo_team_members.sql` 中的演示数据改为仅在开发环境初始化，生产 Flyway 不得创建固定账号。
- 生产管理员改为部署时通过环境变量或一次性初始化流程创建，并强制使用 BCrypt 密码哈希和首次登录改密。
- 删除 `AuthService.passwordMatches` 与 `UserService.updatePassword` 中的明文密码兼容分支。
- 为现有数据库中的明文密码提供一次性迁移方案，并确认迁移后不存在固定默认密码。

### 2. 修正异常 HTTP 状态与错误信息暴露

- `BusinessException` 按业务码返回对应 HTTP 4xx/5xx 状态，不再统一返回 HTTP 200。
- 参数校验错误返回 HTTP 400，未认证和无权限分别返回 HTTP 401/403。
- 未捕获异常只向客户端返回稳定的通用错误信息，禁止返回 `ex.getMessage()`、SQL、堆栈或内部实现细节。
- 同步调整两套前端 HTTP 封装、接口测试、网关监控和内部提醒扫描验收。

## 上线验收门禁

- 上述两项未完成时，只允许在本机或受控测试网络运行。
- 完成整改后重新执行后端测试、两套前端测试与构建、Docker Compose 集成测试和登录安全检查。
