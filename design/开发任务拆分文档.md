# 日程提醒 App — MVP 开发任务拆分文档

> 目标：将 MVP 拆成可执行开发任务，并给出阶段验收标准。

---

## 阶段 1：基础架构

### 后端任务

- 创建 Spring Boot 项目。
- 配置多环境：`dev/test/prod`。
- 接入 MySQL。
- 接入 Flyway。
- 定义统一响应 `ApiResponse`。
- 定义分页请求和分页响应。
- 定义全局异常处理。
- 定义基础错误码。
- 配置 JWT 工具类。
- 配置登录拦截器。

### 前端任务

- 创建 Vue 3 + Vite + TypeScript 项目。
- 接入 Element Plus。
- 接入 Pinia。
- 接入 Vue Router。
- 实现基础布局 `AppLayout`、`AppSidebar`。
- 封装 `api/http.ts`。
- 实现路由守卫。

### 验收标准

- 后端可以启动。
- 前端可以启动。
- 前端能调用后端健康检查接口。
- Flyway 能自动执行初始化迁移。

## 阶段 2：用户系统

### 后端任务

- 创建 `user`、`admin_user` 表迁移。
- 实现注册接口。
- 实现登录接口。
- 实现 refresh token 接口。
- 实现退出登录接口。
- 实现用户资料查询/修改。
- 实现修改密码。
- 实现时区设置。
- 实现管理员登录、退出、资料接口。

### 前端任务

- 登录页。
- 注册页。
- 我的页面。
- 修改密码页。
- 时区设置页。
- 登录态持久化。
- Token 自动刷新。

### 测试重点

- 手机号重复注册。
- 密码强度校验。
- 登录失败提示。
- Access Token 过期后刷新。
- 修改密码后重新登录。

## 阶段 3：个人日程、提醒、通知闭环

### 后端任务

- 创建 `schedule`、`reminder`、`notification` 表迁移。
- 实现个人日程创建、列表、详情、修改、删除。
- 实现完成、取消完成、取消日程、恢复日程。
- 创建日程时根据 `remindAts` 生成 reminder。
- 日程完成/取消时取消 pending reminder。
- 实现提醒扫描任务。
- 提醒到期时生成 notification。
- 实现通知列表、未读数、标记已读、全部已读。

### 前端任务

- 首页今日待办。
- 个人日程列表。
- 新建/编辑个人日程。
- 日程详情。
- 日历页。
- 通知中心。
- `CountdownPill`。
- `TaskTimeline`。
- `StatusTag`。

### 测试重点

- `point_event` 展示为圆点。
- `deadline_task` 展示为截止节点。
- `startTime + deadlineTime` 展示为持续任务。
- 完成/取消日程后提醒取消。
- 提醒扫描生成通知。
- 通知未读数准确。

## 阶段 4：团队功能

### 后端任务

- 创建 `team`、`team_member` 表迁移。
- 创建团队。
- 创建团队时同步创建 owner 成员。
- 生成 6-8 位唯一邀请码。
- 加入团队。
- 查询我的团队。
- 查询团队详情和成员。
- 修改成员角色。
- 移除成员。
- 移除成员后处理其未完成 active assignee 记录。
- 重新生成邀请码。

### 前端任务

- 团队列表页。
- 创建团队弹窗/页面。
- 加入团队弹窗/页面。
- 团队详情页。
- 团队成员页。
- 权限按钮显示。

### 测试重点

- owner 成员一致性。
- 重复加入团队返回 409。
- removed 成员重新加入复用记录。
- admin 不能移除 owner/admin。
- member 看不到管理按钮。

## 阶段 5：团队任务

### 后端任务

- 创建 `team_task`、`team_task_assignee` 表迁移。
- 创建团队任务。
- 批量创建执行人记录。
- 为每个执行人生成 reminder。
- 给执行人发送任务分配通知。
- 查询我负责的团队任务。
- 查询某团队任务列表。
- 查询团队任务详情。
- 编辑标题、描述、分组。
- 修改开始/截止时间。
- 接受、拒绝、完成任务。
- 取消、恢复任务。
- 重新分配 rejected 执行人。
- 修正执行人状态。
- 删除任务。
- 整体状态自动计算。

### 前端任务

- 团队任务列表页。
- 新建团队任务页。
- 团队任务详情页。
- 执行人状态卡片。
- 重新分配弹窗。
- 状态修正弹窗。
- 团队任务时间轴。

### 测试重点

- 创建者不自动成为执行人。
- 执行人必须是 active 成员。
- `pending -> accepted`。
- `pending/accepted -> rejected`。
- `accepted -> completed`。
- `cancelled` 后执行人不能操作。
- 只统计 `is_active=true` 记录计算整体状态。
- `all_rejected` 后重新分配变回 active。
- 重新分配生成新 reminder。

## 阶段 7：联调、测试、优化

### 联调任务

- 对齐 API 字段命名。
- 检查前端路由权限。
- 检查所有列表分页。
- 检查空状态和错误状态。
- 检查时间格式和时区展示。
- 检查通知和提醒闭环。

### 最小验收流程

1. 注册用户 A、B、C。
2. A 创建个人日程，设置提醒。
3. reminder 扫描后，A 收到站内通知。
4. A 创建团队。
5. B、C 通过邀请码加入团队。
6. A 创建团队任务并分配给 B、C。
7. B 接受并完成。
8. C 拒绝。
9. 团队任务整体状态变为 completed。
10. A 重新分配 rejected 记录给 C 或其他 active 成员。
11. 新执行人收到通知和提醒。
12. 管理员后台能查看用户、团队、任务、通知、提醒和日志。

## MVP 完成标准

- 用户端 Web 可以完成登录、日程、团队、团队任务、通知、我的全部主流程。
- 后台可以完成基础管理和查看。
- 数据库迁移脚本完整。
- 所有核心状态流转有测试。
- 所有时间字段按 UTC 存储、ISO8601 返回。
- 提醒与通知联动稳定。
