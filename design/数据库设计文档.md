## 1. 设计约定

### 1.1 通用规则

| 规则 | 说明 |
| --- | --- |
| **时间存储** | 数据库统一存 UTC，接口返回带时区的 ISO8601 格式，用户配置默认时区 |
| **软删除** | 所有业务表支持软删除，使用 `deleted_at` 字段 |
| **唯一索引** | 软删除场景下，唯一索引需考虑 deleted_at，避免已删除记录阻塞新记录 |
| **主键** | 统一使用 `bigint` 自增主键 |
| **审计字段** | 普通业务表包含 `created_at` 和 `updated_at`；日志类/记录类不可变表可只保留 `created_at` |

### 1.2 迁移策略

- 使用 Flyway（推荐）或 Liquibase 进行版本化数据库迁移
- 所有 DDL 脚本通过迁移工具管理，不允许手动修改数据库结构
- 环境切换（本地、测试、生产）通过 Spring Boot 多环境配置切换数据源

### 1.3 命名规范

- 表名：小写字母 + 下划线
- 字段名：小写字母 + 下划线
- 主键：`id`
- 外键：`{目标表}_id`
- 索引：`idx_{表名}_{字段名}`

### 2.1 `user` — 用户表

**约束说明：**
- MVP 阶段手机号全局唯一，包括软删除用户；软删除后手机号不复用，避免账号归属和历史记录混乱

| avatar_url | varchar(500) | 头像 |

| created_at | datetime | 创建时间（UTC） |
| updated_at | datetime | 更新时间（UTC） |

**索引：**
- `uk_user_phone` — phone（唯一索引，包含软删除用户）

**索引：**
- `uk_team_member` — team_id + user_id（唯一索引）

### 2.5 `reminder` — 提醒表（独立表）

**重要：** 将提醒从 schedule/team_task 表独立出来，每个提醒时间一行，便于查询和建索引。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 提醒 ID |
| user_id | bigint | 接收提醒用户 ID |
| target_type | varchar(30) | 关联对象类型：schedule/team_task |
| target_id | bigint | 关联对象 ID |
| remind_at | datetime | 计划提醒时间（UTC） |
| status | varchar(20) | 提醒状态：pending/sent/cancelled/failed |
| sent_at | datetime | 实际发送时间（UTC） |
| error_message | text | 失败原因 |
| created_at | datetime | 创建时间（UTC） |
| updated_at | datetime | 更新时间（UTC） |

**索引：**
- `idx_reminder_status_remind_at` — user_id + status + remind_at
- `idx_reminder_target` — target_type + target_id
- `idx_reminder_user_id_status` — user_id + status

**状态联动规则：**
- 团队任务为每个执行人分别生成提醒，每人有独立提醒记录
- MVP 只给执行人发截止提醒，创建者只收状态变化通知
- 日程/任务完成/取消后，未发送提醒自动取消（status → cancelled）
- 执行人拒绝后，只取消该执行人的提醒
- 任务重新分配后，为新执行人生成新提醒

### 2.6 `team_task` — 团队任务表

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 任务 ID |
| team_id | bigint | 团队 ID |
| creator_id | bigint | 创建者用户 ID |
| title | varchar(200) | 任务标题 |
| description | text | 任务描述 |
| group_name | varchar(50) | 任务分组名称，可为空，默认按团队任务分组 |
| start_time | datetime | 团队任务开始时间（UTC），可为空；用于持续任务时间轴展示 |
| deadline_time | datetime | 截止时间（UTC） |
| status | varchar(30) | 任务业务状态：active/completed/all_rejected/cancelled |
| updated_by | bigint | 最近修改任务的用户 ID |
| time_updated_at | datetime | 任务开始时间或截止时间最近修改时间（UTC） |
| deleted_at | datetime | 删除时间，软删除使用（UTC） |
| deleted_by | bigint | 删除操作者用户 ID |
| created_at | datetime | 创建时间（UTC） |
| updated_at | datetime | 更新时间（UTC） |

**索引：**
- `idx_team_task_team_id` — team_id
- `idx_team_task_creator_id` — creator_id
- `idx_team_task_status` — status
- `idx_team_task_deadline_time` — deadline_time
- `idx_team_task_start_time` — start_time

**团队任务整体状态计算规则：**

团队任务整体状态只基于 `is_active = true` 的执行人记录计算，历史分配记录不参与整体状态计算。

| 执行人状态组合 | 任务整体状态 |
| --- | --- |
| 存在 pending 或 accepted | active |
| 全部 completed | completed |
| 全部 rejected | all_rejected |
| 有 completed + rejected，无 pending/accepted | completed |

### 2.7 `team_task_assignee` — 团队任务执行人表

**约束说明：**
- 每个 `task_id + user_id` 只能有一条 `is_active = true` 的记录
- `task_id + user_id + assign_round` 唯一

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 记录 ID |
| task_id | bigint | 任务 ID |
| user_id | bigint | 执行人用户 ID |
| assign_round | int | 分配轮次，从 1 开始 |
| is_active | boolean | 是否当前有效记录 |
| status | varchar(20) | 状态：pending/accepted/rejected/completed |
| accepted_at | datetime | 接受时间（UTC） |
| rejected_at | datetime | 拒绝时间（UTC） |
| completed_at | datetime | 完成时间（UTC） |
| reassigned_from_user_id | bigint | 重新分配来源用户 ID，可为空 |
| assigned_by | bigint | 分配或重新分配操作者用户 ID |
| assigned_at | datetime | 分配/重新分配时间（UTC） |
| status_updated_by | bigint | 最近修改状态的用户 ID |
| status_updated_at | datetime | 状态最近更新时间（UTC） |
| created_at | datetime | 创建时间（UTC） |
| updated_at | datetime | 更新时间（UTC） |

**索引：**
- `uk_task_user_round` — task_id + user_id + assign_round（唯一索引）
- `idx_assignee_task_id` — task_id
- `idx_assignee_user_id` — user_id
- `idx_assignee_is_active` — task_id + is_active（仅 active 记录）

**重新分配规则：**
- 只允许对 `rejected` 的执行人重新分配
- 原记录 `is_active = false`，新记录 `pending + is_active = true` + `assign_round` 加 1
- `all_rejected` 后重新分配，任务整体状态自动变回 `active`
- 只能重新分配给当前团队内 `status = active` 的成员
- 成员被移除时，其未完成执行记录保留原状态，但 `is_active` 设置为 `false`，避免任务被已移除成员卡住；管理员可手动重新分配给 active 成员

## 4. 数据规则汇总

### 4.1 时间与时区

| 规则 | 说明 |
| --- | --- |
| 数据库存储 | 统一存 UTC |
| 接口返回 | 带时区的 ISO8601 格式，例如 `2026-07-23T09:00:00+08:00` |
| 前端显示 | 根据用户配置的 `timezone` 字段转换显示 |
| AI 解析 | 明确基于用户所在时区 |

### 4.2 软删除

| 规则 | 说明 |
| --- | --- |
| 软删除字段 | 统一使用 `deleted_at`（datetime，UTC） |
| 查询过滤 | 默认查询带 `WHERE deleted_at IS NULL` |
| 唯一索引 | 软删除场景下，唯一索引需要考虑 `deleted_at`，避免已删除记录与未删除记录冲突 |

### 4.3 外键策略

| 规则 | 说明 |
| --- | --- |
| 逻辑外键 | 使用 `bigint` 字段关联，不强制使用数据库外键约束 |
| 业务校验 | 在应用层进行外键合法性校验 |
| 原因 | 提高性能，方便软删除和分库分表扩展 |

### 4.4 提醒与任务状态联动

| 场景 | 规则 |
| --- | --- |
| 日程完成后 | 未发送提醒自动取消 |
| 团队任务完成/取消后 | 未发送提醒自动取消 |
| 执行人拒绝后 | 只取消该执行人的提醒，不影响其他人 |
| 任务重新分配后 | 为新执行人生成新提醒 |
| 团队任务提醒 | 为每个执行人分别生成提醒，每人有独立提醒记录 |
| MVP 提醒范围 | 只给执行人发截止提醒，创建者只收状态变化通知 |

## 5. 实体关系概览（MVP）

```
user ───< schedule          用户拥有个人日程
user ───< team_member >─── team   用户通过成员关系加入团队
user ───< team_task          用户创建团队任务（creator）
team ───< team_task          团队包含团队任务
user ───< team_task_assignee   用户被分配团队任务（执行人）
team_task ───< team_task_assignee   团队任务对应多个执行人
user ───< reminder          用户接收提醒
user ───< notification      用户接收通知
admin_user ───< admin_operation_log   管理员产生操作日志
```
